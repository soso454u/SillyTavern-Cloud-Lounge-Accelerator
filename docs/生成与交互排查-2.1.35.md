# 2.1.35 生成与交互排查

## 报告能确认的范围

2026-10-24 的报告来自插件 2.1.34、SillyTavern 1.18.0 release `51ad27fb8`。导出时没有生成，聊天共 138 条，页面渲染 5 条。报告只保存了一份最近交互异常，不是完整的运行性能追踪。

- 交互快照为 `main-thread-busy`，定时器响应延迟 309ms；触点是最后一条聊天中的 `q` 文本节点，未记录复制按钮、业务异常、残留遮罩或弹窗。触屏指针捕获按正常路径释放。
- Long Tasks API 为 unsupported，空 longTasks 数组不代表没有卡顿。定时器延迟也可能包含系统菜单或页面调度暂停，不能单独证明有一项 309ms 的脚本长任务。
- 启动设置响应压缩后 7,861,821 字节，解压后 66,292,786 字节。它可能增加解析和常驻内存负担，但报告没有内存峰值、进程退出原因或数据组成，不能认定是本插件、某个其他扩展或设置大小导致了闪退。
- 启动阶段记录到约 84.8 秒，与之后的生成/点击现场不在同一时刻；不能把启动请求等待直接当成生成卡顿原因。

## 源码中已确认的额外工作

1. 旧诊断在每次 pointerdown 的捕获阶段读取六层 computed style、命中栈和弹窗状态，可能迫使尚未提交的流式布局立即计算。自愈模块也会在任意 pointerup 时先测量聊天输入框，即使用户点的是复制按钮。
2. 全局弹窗 observer 会查询流式生成中新添加/移除的每个消息子树，查找实际上位于聊天区域之外的原生 popup。
3. 每个代码块完成高亮后，旧代码删除整条消息的所有复制按钮，再调用官方 helper。官方 `addCopyToCodeBlocks()` 会遍历传入范围内的所有 `pre code`，因此多代码块消息会重复工作，重建按钮也会丢掉原节点。

这些是可由插件代码和隔离检查确认的问题，并不能反向证明它们就是用户所述“闪退”的根因。

## 修改和验证

2.1.35 将诊断的丰富快照移到疑似故障的事件后检查；普通成功点击不读取上述布局信息。生成期间断开代码观察，弹窗监听跳过聊天子树。高亮任务去重，保留原生复制按钮及监听器；选区/按住期间暂缓，超长代码保留为纯文本。原生消息接收、生成帧率、淡入设置及聊天/设置保存协议未修改。

自动测试覆盖这些边界；`scripts/check-chat-interaction.mjs` 在隔离 Chromium 桌面/触屏环境验证真实 DOM 选区、指针、弹窗生命周期，以及按钮节点/处理器保留、扫描暂停和普通点击零同步样式/命中读取。该检查模拟 SillyTavern API 和 highlight.js 的 DOM 替换行为，没有加载用户聊天、预设或外部扩展。

还需用户现场确认“闪退”是整个应用退出、页面刷新/白屏，还是面板关闭。未捕获退出现场，也未在原生 Safari 进程或用户的完整扩展组合中验证；本版不宣称已修复浏览器进程崩溃。
