# 2.1.38 生成与正则操作排查

## 新报告的证据边界

用户提供的 2.1.37 报告对应 SillyTavern 1.18.0 `51ad27fb8`。导出时没有生成，聊天共 201 条，已显示 5 条；交互快照记录扩展抽屉按钮完整点击后约 255ms 的响应延迟，没有残留指针捕获或阻塞弹窗。WebKit 不支持 Long Tasks API，不能用空数组排除长任务。

启动设置解压后约 65.6MB、APP_READY 约 164 秒是启动阶段数据。它们与较晚的生成和截图不在同一时刻，不能当作生成帧耗时，也不能据此判断哪些正则慢。截图中的气泡截断与空白是可见现象，没有合成层/渲染任务追踪，尚不能证明唯一原因。

本版没有删除或禁用用户的正则，也没有依据正则条数自动改变作用范围。

## 代码中确认并修正的问题

1. **慢预览没有真正休息。** 2.1.36–2.1.37 用开始时刻加一个至多 125ms 的间隔计算下次期限。若原生工作本身已超过 125ms，结束时期限已经过去，下一次预览可能立即开始。现在使用完成时刻加恢复间隔；例如 300ms 的原生预览完成后额外等待 600ms，最终渲染始终不节流。触屏生成时减少不断重建的大气泡毛玻璃图层，结束后恢复主题；不重写全局主题或保存用户帧率/淡入设置。
2. **批量删除重复上传。** [原生 regex/index.js](https://github.com/SillyTavern/SillyTavern/blob/51ad27fb8/public/scripts/extensions/regex/index.js) 的批量删除循环逐条调用删除；每条预设/角色规则都要等待一次原生保存。最后重建列表并完整重读聊天。现同范围先合成剩余规则，调用一次官方 `saveScriptsByType`，成功后移除对应 DOM 行，再统一通知精准刷新。不同范围分别确认结果；取消或会话已变化不写入，部分成功会明确提示。
3. **保存的额外工作和竞态。** 保留官方持久化接口及服务器确认，移除额外的大设置保存与整套编译缓存清空。原生编译器按展开后的完整查找式缓存，新查找式自然使用新键，无需清掉其他规则。编辑按钮即时显示忙状态并防重复排队；点击时捕获草稿及会话范围，无修改跳过写入；等待时又输入的新草稿不被关窗丢弃。原生内存已接收本次数组但服务器写入抛错时，仅还原仍由本次持有的数组，不覆盖后来的外部修改，也不自动重试删除。
4. **划选依赖稀疏命中。** 原实现只处理每次 pointermove 当时命中的一行，快速跨越时会漏选，并且每条 change 都触发原生工具栏扫描。现在捕获当前指针，按视觉顺序补齐跨越的行，每帧合并通知；边缘滚动只在手势期间运行。独立 ↪ 处理分类设置，☰ 仍负责原生实际顺序；归组不改正则定义、权限或执行顺序。

5. **普通滑动的绘制开销。** 用户补充无生成时也会出现内容延迟绘制。其 iMessage CSS 的长 `.mes_block::before` 同时使用遮罩和 `blur(16px)` 等实时滤镜；本版在触屏聊天滚动期间继承覆盖该滤镜，并对气泡与伪元素临时禁用 backdrop-filter，停止滚动约 200ms 后恢复。不移除遮罩、不改背景填充、尺寸或滚动位置，不隐藏消息。复用已有被动监听与一个尾部计时器；无轮询、无消息扫描，切换聊天、后台和停用均清理。它针对绘制负担提供减负，不能据此证明主题滤镜是所有卡顿的唯一原因。
6. **等价整理及重复工作。** 合集选择、当前结果、Shift 连选和清空选择共用批量更新入口；官方行 change 处理器读取全体勾选状态，故只需一次通知。归组先按范围缓存 ID 集合，验证全部行后每范围一次复制分类映射；一千条规则仍保持原始内容和执行顺序。分组改名也改为一次合并映射，保留 `__proto__` 等特殊 ID 的自有数据键语义。样式只合并完全相同的声明或相同作用域内公共部分，保留媒体条件和优先级；没有按名称相近去删用户正则。

## 验证

- `npm test`：219 项通过，含慢预览恢复、最终渲染、普通滚动及后台/切换清理、千条归组、批量删除写入次数、部分失败与内存恢复、无修改保存、切换竞态和编辑期间继续输入。
- `scripts/check-regex-operations.mjs`：真实鼠标及触屏事件验证快速跨行选择、同范围多选拖动归组、调整顺序模式归组、取消与清理、慢请求期间保留行、十条预设规则一次保存、重复点击与新草稿保留。数据和原生依赖是隔离替身，不连接用户酒馆。
- `scripts/check-client-bundle.mjs`：运行正式发布文件，验证桌面/模拟 iPhone 的 token 事件、最终 DOM/聊天正文、原生偏好与设置接线、无生成时的滚动减负及气泡高度/阅读位置/正文不变、生成结束恢复、停用和延迟启动。加载用户当前 iMessage CSS 后额外核对真实滤镜被暂时禁用并恢复，遮罩、背景填充、宽高、正文与阅读位置保持一致。
- `scripts/check-regex-collections.mjs`：载入用户当前美化 CSS，检查分组改名/新建/持久化、窄侧栏、大字体、长名称及原生列表顺序。
- `scripts/check-chat-interaction.mjs`：既有复制按钮、选区、弹窗和生成期间扫描暂停回归。
- `scripts/check-native-streaming.mjs`：直接执行固定版本官方 `StreamingProcessor` / `Stopwatch` 的普通、继续、Swipe 正常及停止六组流程；最终正文、reasoning、token 计数和保存完整。

新版复制诊断中的 `streaming` 仅记录本次页面会话的预览次数、跳过次数、最慢/最近预览耗时与恢复间隔，不记录正文、表达式或替换文本。该耗时包含 `onProgressStreaming()` 内 await 的工作，并非纯正则执行时间；它可确认优化是否实际接管以及原生预览有多重，不能直接点名某条正则。单次很重的原生同步任务仍不能被插件拆分；本版未在用户 iPhone、完整主题和扩展组合上现场验证。
