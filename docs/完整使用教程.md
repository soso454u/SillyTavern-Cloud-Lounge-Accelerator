# 云酒馆加速器 2.1.31 完整使用教程

## 一、先选择安装模式

云酒馆加速器由两部分组成：

- UI 扩展：页面启动、聊天、正则、预设、拖拽和抽屉优化。
- 服务端插件：提供根作用域 Service Worker，用于程序静态资源缓存。

| 你的环境 | 推荐方式 |
| --- | --- |
| 自己管理 SillyTavern 服务器、容器或本机目录 | 安装 UI + 服务端插件 |
| 只能在酒馆内安装扩展 | 只安装 UI |
| 没有 HTTPS，也不是 localhost | 先用 UI；静态缓存会显示“需要 HTTPS” |

只安装 UI 也能使用聊天和界面优化。服务端插件缺失不会阻止扩展启动。

### 多用户环境的更新权限

一键安装器将 UI 扩展放在 `public/scripts/extensions/third-party/`，属于所有账号共享的全局扩展。SillyTavern 只允许管理员账号更新全局扩展；普通账号可更新自己安装在个人目录里的扩展。

如果出现“你没有更新全局扩展程序的权限”，请切换到酒馆管理员账号，再打开扩展管理器更新加速器。无需关闭多用户，也无需给朋友的普通账号提升权限。若同时需要更新服务端插件，请由管理服务器的人重新执行一键安装命令，并重启酒馆。

其他插件可以更新并不代表此账号有全局扩展更新权限：它们可能是个人安装。这个权限提示与世界书面板误关闭无关。

## 二、一键安装完整增强

下面四段命令分别对应你提供的 VPS、Android、Mac 和 Windows 部署教程。它们同时用于首次安装与以后更新：安装器会更新服务端插件和 UI 扩展，并只在配置实际变化时备份和写入，不会自动启动或重启 SillyTavern。

### VPS / 1Panel XTerminal

教程使用 `root` 用户把酒馆安装在 `/root/SillyTavern`，直接复制：

```bash
cd /root/SillyTavern
curl -fsSL https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.sh | bash
```

如果你用的不是 `root` 用户，或者酒馆不在这个位置，只修改第一行路径。

### Android / Termux

安卓教程把酒馆安装在 Termux 用户目录的 `~/SillyTavern`。先保证 Termux 有 `curl`，再执行安装：

```bash
pkg install curl -y
cd ~/SillyTavern
curl -fsSL https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.sh | bash
```

请在 Termux 中执行，不是在手机浏览器地址栏或 MT 管理器中执行。安装后重新运行 `cd ~/SillyTavern && bash start.sh`。

### Mac / 终端

Mac 教程把酒馆安装在当前用户目录的 `~/SillyTavern`，在“终端”中直接复制：

```bash
cd ~/SillyTavern
curl -fsSL https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.sh | bash
```

安装后重新运行 `cd ~/SillyTavern && ./start.sh`。

### Windows / PowerShell

Windows 教程的实际酒馆根目录是 `D:\SillyTavern\SillyTavern`。请打开 PowerShell（不是 CMD），复制：

```powershell
& ([scriptblock]::Create((irm 'https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.ps1'))) -SillyTavernRoot 'D:\SillyTavern\SillyTavern'
```

如果你安装在其他盘或其他文件夹，只替换最后的路径。安装后关闭旧的 SillyTavern 窗口，再双击根目录中的 `Start.bat`。

### 自定义路径通用写法

Linux、Android 和 Mac 也可以不先 `cd`，直接把真实根目录传给脚本：

```bash
curl -fsSL https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.sh | bash -s -- /你的/SillyTavern/路径
```

脚本完成后请手动重启 SillyTavern。安装器不会猜测并重启你的 Termux 进程、Mac 终端、Windows 窗口、1Panel 容器或系统服务。

普通安装/更新会默认开启聊天保存上传压缩，避免大聊天按原始体积重复上传；可用 `--no-chat-compression`（PowerShell 为 `-DisableChatCompression`）明确关闭。Keep-Alive 和角色卡懒加载仍不默认改动：VPS、Android 和 Mac 可追加 `--keep-alive`、`--lazy-characters` 或 `--fast-start`；PowerShell 对应使用 `-KeepAlive`、`-LazyCharacters` 或 `-FastStart`。`FastStart` 只是后两项的组合，不代表所有环境都一定更快。

一键安装会：

1. 把仓库安装到 `plugins/cloud-lounge-accelerator/`。
2. 把 UI 文件安装到默认用户的扩展目录。
3. 仅当配置需要调整时保存安全备份并写入。
4. 自动启用并验证 `enableServerPlugins: true`。
5. 默认启用 `performance.requestCompression`：256KB 以上请求压缩、无 8MB 上限、超时 15 秒。

## 三、手动安装

### 只安装 UI

在 SillyTavern 中打开“扩展 → 安装扩展”，输入：

```text
https://github.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator
```

安装后刷新页面。打开“扩展设置 → 云酒馆加速器”即可看到三个开关。

### 安装服务端插件

进入 SillyTavern 根目录：

```bash
git clone https://github.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator.git plugins/cloud-lounge-accelerator
```

已有目录时更新：

```bash
git -C plugins/cloud-lounge-accelerator pull
```

确认目录结构：

```text
SillyTavern/
├─ plugins/
│  └─ cloud-lounge-accelerator/
│     ├─ package.json
│     ├─ manifest.json
│     ├─ index.js
│     └─ server/
│        ├─ index.js
│        └─ worker-template.js
└─ config.yaml
```

确认 `config.yaml`：

```yaml
enableServerPlugins: true
```

角色较多时可再确认 SillyTavern 官方性能设置：

```yaml
performance:
  lazyLoadCharacters: true
  memoryCacheCapacity: '100mb'
  useDiskCache: true
  requestCompression:
    enabled: true
    minPayloadSize: '256kb'
    maxPayloadSize: 0
    timeout: 15000

cacheBuster:
  enabled: false
```

不要创建重复的 `performance:` 或 `cacheBuster:` 段；只修改现有配置项。

重启后，日志应包含：

```text
Initializing plugin from .../cloud-lounge-accelerator/server/index.js
```

## 四、配置 HTTPS

Service Worker 只能在 HTTPS 或 localhost 使用。云服务器上应从 `https://你的域名` 访问，而不是裸 `http://IP:端口`。

没有自有域名时，可以使用 `sslip.io` 这类把 IP 编入主机名的公共解析服务。例如服务器 IP 为 `23.94.194.240`：

```text
23-94-194-240.sslip.io
```

在 1Panel 中：

1. 新建反向代理网站，主域名填上述主机名。
2. 上游填 `http://127.0.0.1:8000`，端口按实际修改。
3. 用 HTTP 验证申请 Let's Encrypt 证书。
4. 开启 HTTPS，并传递 `X-Forwarded-Proto $scheme`。
5. 此后从 HTTPS 地址进入酒馆。

如果证书报错、页面不是安全上下文或浏览器策略禁用 Service Worker，页面缓存会保持关闭，其他优化仍可使用。

## 五、1Panel 反向代理静态优化

仓库中的 [`1panel/nginx-static.conf.example`](../1panel/nginx-static.conf.example) 只匹配程序静态目录。

操作前：

1. 备份当前站点配置。
2. 把片段放进已有 `server { ... }` 内。
3. 把 `proxy_pass http://127.0.0.1:8000;` 改为当前 SillyTavern 上游。
4. 如已有相同正则 `location`，合并配置，不要叠加冲突规则。
5. 通过 1Panel 配置检查后再重载 OpenResty/Nginx。

不要缓存以下内容：

```text
页面导航
/api/
/characters/
/backgrounds/
/thumbnail
/user/
登录页和认证响应
```

## 六、开关如何工作

### 页面加载加速

开启后：

- 启动阶段短时间合并完全相同的安全请求。
- `APP_READY` 后探测服务端插件。
- 用 HEAD 请求检查 `/style.css` 与 `/script.js` 的实际响应缓存头；两者都至少还能保持 5 分钟新鲜时，注销本插件 Worker 并使用浏览器原生 HTTP/disk cache。
- 从服务端健康接口读取不含凭据的程序版本签名。
- 没有可靠原生缓存时，把版本签名发送给 Worker；SillyTavern 核心文件变化时会清理旧程序缓存。
- Worker 模式只在空闲时预热一次。
- iPhone/iPad 不提前隐藏官方 `app-init` loader；页面会等到 `APP_READY` 再开始交互看护，避免慢启动时出现“看到按钮但尚未可点”。

Worker 不接管页面导航。Basic Auth 的 `401` 挑战、反向代理认证、登录跳转都由浏览器原生处理。

### 聊天与重美化优化

开启后自动执行：

- 聊天读取响应完全交给 SillyTavern 原生消费，不复制或二次解析完整聊天；复杂度判断复用官方已经解析的内存数据并只检查最近 40 条。
- 打开任何角色聊天时默认只先加载最后 5 条消息；在加速器的“聊天显示”页可调整为 1–50 条。
- 切换聊天后的首秒内使用 SillyTavern 官方滚动接口保持最后一条可见；用户一旦触碰聊天或加载历史消息便立即取消。
- 点击“显示更多”时使用 SillyTavern 原生流程按同一页数补载旧消息；插件先登记当前会话，不会把补载事件误判成首次进入，也不二次修改 `scrollTop`。
- 最近代码优先高亮，旧代码按需高亮并折叠预览。
- 完整 HTML 源码即使没有 `language-html` 类名也会跳过语法高亮，复制按钮和最终美化仍可正常使用。
- 流式生成期间不再随每次 DOM 变化扫描全部代码块；点击停止后会先等待官方生成状态解锁，再合并扫描一次。
- 移动端纵向滚动不再轻易误触左右 Swipe。
- 编辑已有正则、单条开关和批量开关不会立即拆掉整段聊天；插件会比较改动前后的正则，只刷新原始消息中可能匹配的内容。
- 修改状态栏正则时，未包含状态栏标记的剧情选项会保持现有界面；只改名称或只影响提示词时不刷新聊天。
- 调整正则顺序、作用范围，或遇到无法安全判断的宽泛查找式时，会分帧刷新全部已显示消息。
- 正则面板的“整理正则”可按名称搜索、范围与合集筛选，支持 `[合集名]` / `【合集名】` / `〔合集名〕` / `「合集名」` / `『合集名』` 前缀。“合集自动折叠”默认开启：标题就在原正则列表里，展开后完整正则行集中显示在标题下方；未分类默认展开，关闭整理栏后仍可折叠。
- 合集标题旁的“选择此合集”在收起状态也可一键勾选；搜索或筛选时只选择匹配结果。需要拖拽排序时点“调整顺序”，完成后点“返回合集”。关闭“合集自动折叠”会恢复原列表和原生拖拽手柄；分组显示不会修改正则实际执行顺序。
- 全局、预设、角色的合集各自展开或收起，同名合集和“未分类”也不会跨范围联动。
- 分组标题旁点“改名”可编辑分组名称，包括把当前未分类规则归为自定义名称；确认后不修改正则自己的名称和内容。
- 打开“整理正则 → 管理分组”，输入名称、选择全局/当前预设/当前角色，再点“新建分组”，可以先创建没有规则的空组。勾选规则后，选择目标组并点“将已选正则移入分组”；选择“移至未分类”可把它们移回。分类随酒馆设置保存，不同预设和角色分别记录，不改变正则顺序或启用状态。
- 整理框按实际侧栏宽度自动排版并沿用当前主题样式。手机或窄栏里下拉框与按钮会换行，长组名会折行，长正则名称省略显示并保留完整名称提示。
- 开启批量编辑或整理栏后，点正则名称就能勾选；电脑可 Shift 连选，触屏可显式开启“按住名称划选多条”。后续批量操作仍用官方按钮。
- 拖动行内 ↪ 可以归组：松手到分组标题或浮出的分组目标即可；拖动已选行时，同一范围内其他已选规则一起归组。“调整顺序”模式也支持 ↪，原来的 ☰ 仍用于原生执行顺序。归组手势取消或拖到无效区域不会保存。
- 划选现在会补齐快速跨过的中间行，并按帧合并原生工具栏通知；靠近滚动区域边缘可自动滚动。未开启划选时，名称区保留正常页面滚动。
- 单条/批量删除仍需确认，但同范围合并保存一次，成功后才移除；失败保留未完成项并提示。编辑保存有处理中提示与重复提交保护，无修改直接关闭；等待时继续输入的新内容会保留供再次保存。原生服务器的保存等待无法完全消除。

聊天文件保存与历史上下文需要区分：

- SillyTavern 保存聊天时仍会把完整聊天数组交给官方 `/api/chats/save`，服务端继续执行完整性检查、原子覆盖和备份。加速器不改变这层数据语义，而是启用官方 gzip，使 15MB 等大请求以压缩后的字节量通过网络；压缩失败或超时会由官方逻辑回退原始请求。
- 加速器默认把 `chat_truncation` 设为 5，并允许在“聊天显示”页调整；它只控制页面渲染多少条消息，内存中的 `chat` 数组、磁盘 JSONL 和发给模型的上下文选择不会因此被截断。
- 对 Chat Completion 预设，`chatHistory` 是官方内置 marker。预设禁用或遗漏它时，SillyTavern 会跳过历史消息集合的构建，看起来就像模型“读不到旧记录”；聊天文件本身通常仍在。遇到这种情况请在预设的提示词管理器中恢复并启用 `chatHistory`，再查看提示词检查器确认历史消息实际进入请求。

“重新渲染当前聊天”适合修改正则后立即更新当前已显示消息。它先使用局部消息接口；单条失败只显示错误数，接口整体缺失时保留聊天并提示，不重新读取或保存聊天。切换聊天、生成开始或插件停用时取消尚未执行的刷新。

触屏普通滑动时，聊天优化也会临时减轻气泡的实时毛玻璃，滚动停稳约 200ms 后恢复；不会隐藏消息或改变高度、阅读位置和正文。生成中的预览减负与普通滚动独立结束，切换聊天、后台或停用会清理临时样式。

### 界面操作优化

开启后自动执行：

- 普通点击不触发诊断的多层样式/命中栈读取，也不测量无关聊天输入框；只有疑似异常才在事件处理完成后补充快照。原生代码复制在 pointerup 执行，随后主动停止 click 冒泡不再被误判为传播故障。
- 预设、正则和世界书完全使用 SillyTavern 原生 sortable 和顺序保存逻辑。
- 电脑与手机的预设都只允许从左侧 ☰ 手柄开始排序，至少按住 150ms 并移动 10px，保留更严格的原有阈值。名称、开关、编辑区的点击与滑动翻页不会触发排序。正则和世界书继续保留各自原生拖拽方式。
- 原生预设列表刷新或切换后，插件在下一次按下的捕获阶段重新设置手柄和阈值，不增加 DOM observer 或轮询；只修改原生 sortable 的这三项选项，不替换其条目规则和排序保存回调。停用后恢复原有选项，并保留其他扩展后续单独修改的值。
- 插件不禁用官方 sortable，不在拖动期间延迟重建预设列表。只有显式开启正则“按住名称划选多条”时，才在名称区处理该次划选手势；官方拖拽手柄不受影响。
- 生成期间点击预设开关会立即更新图标、当前行样式和官方设置，不执行 Token dry-run，也不重建列表。
- 手机和触控笔必须在同一预设开关上按下并抬起，且没有滑动超过 10px 或发生系统取消，才会即时切换并过滤后续重复 `click`；鼠标在 click 时切换。翻页、划过其他开关、滑出后滑回均不会误切换；只有开关点按期间临时监听 pointermove，结束或停用后移除。
- 所有平台上如果 SillyTavern 弹窗已经进入关闭状态，或加载内容已移除但透明 modal 仍留在 top layer，插件会在安全延迟后解除点击封锁。
- 仍有 SillyTavern 官方活动阻塞任务时不会清理遮罩；快捷回复的透明最小化执行窗被点到时只会展开，不会自动终止脚本。
- 用户明确点按 `#send_textarea` 但焦点失败时，插件才检查控件状态与 hit-test；正常可输入且没有合法 modal 时恢复焦点，不会周期性抢走世界书、正则或 Popup 输入框的焦点。
- 输入框与软键盘保持 SillyTavern 原生布局。iPhone/iPad 上点按聊天输入框后，插件会在键盘视口变化和短时延迟检查中调用浏览器原生 `scrollIntoView()`，解决第三方输入法要等输入第一个字才让输入区显现的问题；不会平移输入区，也不会修改聊天高度、聊天滚动、文字或输入选区。键盘收回后由原生布局自然归位。
- 残留层挡住按钮时只解除 blocker，不自动重放按钮点击；高级信息会显示最近恢复原因、阻塞元素与累计次数，控制台同时记录浏览器和触控环境。
- 抽屉与角色详情的前后层级沿用酒馆原生规则；插件不再把该规则限制成仅桌面生效，确保手机上从角色卡跳转的世界书能正常接收点击。
- 桌面顶栏抽屉打开/关闭保持 160/130ms；1000px 以下粗指针设备的普通顶栏抽屉一次完成高度布局，仅用 `transform + opacity` 动画，普通触屏为 90/70ms，iPhone/iPad 为 80/60ms。
- 手机普通顶栏抽屉打开期间持续停用 `backdrop-filter`，避免结束瞬间重新创建 blur 图层；`.fillLeft` / `.fillRight`、桌面布局和“减少动态效果”不接管。
- Popup 使用 SillyTavern 官方 `[opening]` / `[closing]` 状态应用对应档位，插件不额外设置 `pointer-events: none`。对于确认残留的弹窗，优先调用所属 Popup 的取消完成流程；已经进入关闭状态的弹窗保留其原本结果。
- 预设、世界书和正则开始拖动后，CSS 只匹配当前面板里的官方 `.ui-sortable-helper` / Sortable helper，临时移除面板模糊、阴影和过渡；松手后 helper 消失即自动恢复。
- 系统启用“减少动态效果”时，不覆盖 SillyTavern 的抽屉和 Popup 动画设置。
- 全平台自愈的 body observer 只筛选弹窗新增/移除；每个弹窗只观察自身 `open/closing` 和子节点增删，不监听子树 class，同一帧内的多次变化只扫描一次；触屏 guard 不再重复观察弹窗。
- 生成真正解锁后，多次开关会合并为一次官方 `renderDebounced()`，重算 Token 并恢复完整列表。

生成期间的切换只影响下一次生成、继续或重新生成，不会改变已经发送给模型的当前请求。

聊天优化还会在生成开始时断开代码块 MutationObserver，真正解锁后重新连接并延后 180ms 扫描；弹窗的全局结构监听不搜索聊天消息新增的 HTML 子树。高亮队列对同一代码块去重，保留原生复制按钮的 DOM 节点与监听器；用户按住消息或在聊天中选中文字时暂缓高亮，松开/清除选区后恢复。完整 HTML 文档和超过 20,000 字符的代码跳过语法解析，原文与复制仍保留。

“主线程繁忙”报告来自定时器延迟信号，并非浏览器崩溃日志；系统菜单、应用切换也可能推迟定时器。遇到页面自动刷新、白屏或整个应用退出，需要结合具体表现继续排查，不能仅凭这个标签确定原因。

### 云端性能优化

完整安装后，面板会读取 SillyTavern 根目录的 `config.yaml`，并提供三个互不绑定的开关：

- `聊天保存上传压缩`：超过 256KB 的设置或聊天保存请求使用 SillyTavern 官方 gzip，取消默认 8MB 上限并把超时放宽到 15 秒；压缩失败会自动回退未压缩请求。普通一键安装/更新默认开启。
- `HTTP Keep-Alive`：可能减少 SillyTavern 后端 HTTP/HTTPS 请求反复建连的开销；某些网络、代理或 API 环境可能出现 `ECONNRESET`、连接中断等异常，遇到后应关闭。
- `角色卡懒加载`：角色超过约 1000 张时通常更有价值；部分未适配的第三方扩展可能失效，高级模糊角色搜索会退化为只按角色名搜索。

开启高风险选项前会再次确认。只有内容实际变化时才写入；写入或验证失败会自动恢复修改前内容。备份目录固定为：

```text
<SillyTavern>/.cloud-lounge-accelerator/backups/
├─ config.original.yaml       ← 首次修改前永久基线，不覆盖
├─ config.20260810-120000-000.yaml
├─ config.20260811-180000-000.yaml
└─ config.20260812-043500-000.yaml
```

滚动快照只保留最近 3 份不同内容；配置已经是目标状态时不会重写，也不会新增备份。关闭开关会把对应值写回 `false`。所有修改均需重启 SillyTavern 才会影响正在运行的服务器。

## 八、修复插件

遇到以下情况可以点击“修复插件”：

- 更新后仍出现旧样式。
- Worker 状态异常。
- 缓存资源数长期为 0。
- 页面加载优化未恢复。

修复流程只会停止并重启本插件、注销本插件 Worker 并清理本插件缓存；如果服务器没有可靠原生缓存，再重新注册和预热 Worker。不会删除聊天、角色卡、预设、世界书或服务端配置。

页面完全打不开或尚未完成认证时，部署当前版本后在浏览器站点设置中最后清理一次该域名的 Service Worker/站点缓存，然后重新登录。新 UI 发现服务端仍是旧版时会自动注销 Worker，不再把旧 Worker 装回来。当前版本不提供会整页跳转的“本次安全模式”按钮。

## 九、更新与卸载

服务端目录更新：

```bash
git -C plugins/cloud-lounge-accelerator pull
```

UI 扩展可从 SillyTavern 扩展管理器更新。更新完成后刷新页面；服务端文件变化后重启 SillyTavern。

从 2.0.x 早期版本升级到当前版本时：

- 旧设置自动迁移为三个开关。
- 旧版保存的聊天截断原值会恢复。
- 旧 `cloud-lounge-static-*` 缓存在 Worker 激活时清理。
- 不再识别或生成 `?cla-safe=1` 页面跳转。
- UI 与服务端版本不一致时自动停用并注销本插件 Worker；服务端目录必须同步更新并重启 SillyTavern。
- 第一次运行 2.1.3 安装器时，旧 `config.yaml.backup-cloud-lounge-*` 会自动迁入专用备份目录并去重；迁移成功后只清理本插件旧命名文件，不处理用户自己的备份。

卸载时应同时移除 UI 扩展和 `plugins/cloud-lounge-accelerator/` 服务端目录，再重启 SillyTavern。UI 扩展的删除 Hook 会注销本插件 Worker 并清理本插件缓存。

## 十、常见问题

### 显示“仅 UI 模式”

服务端插件没有加载。只需要前端优化时这是正常状态；需要静态缓存时，检查安装路径、`enableServerPlugins: true` 和重启日志。

### 显示“需要 HTTPS”

检查地址是否为 HTTPS、证书是否有效，以及反向代理是否正确传递协议头。

### 域名 Basic Auth 弹不出来

先确认 UI 扩展和服务端插件都已更新到当前版本，并在更新服务端后重启 SillyTavern。然后在浏览器站点设置中最后清除一次该域名的旧 Service Worker。新版不会接管页面跳转；如果以后两处版本再次不一致，UI 会自动注销旧 Worker 并停止重新注册。

### 显示“服务端插件需更新”

酒馆内的自动更新只更新了 UI 扩展，服务端插件还是旧版。运行一键安装/更新脚本同步两个目录，重启 SillyTavern，再刷新页面。版本一致后页面缓存会自动恢复。

### iOS 主屏幕第二次打开显示 Unauthorized

当插件检测到“iOS 主屏幕独立 Web App + HTTP Basic Auth”组合时，会进入 iOS 兼容模式：自动注销本插件旧 Worker、清理本插件静态缓存并停止重新注册。页面加载加速开关仍保持开启，因为启动请求合并、聊天、正则和交互优化会继续工作。

升级步骤：

1. 同步更新 UI 扩展和服务端插件到 2.1.31。
2. 重启 SillyTavern。
3. 先在 Safari 普通网页中确认可以正常认证并进入。
4. 删除旧主屏幕图标，再从 Safari 重新添加到主屏幕。
5. 第一次成功进入后，在“高级信息”确认显示“iOS 兼容模式 / iOS 主屏幕 + Basic Auth”。

如果仍出现 Unauthorized，可在添加主屏幕时关闭“作为 Web App 打开”，让图标改用 Safari 的认证状态；或者改用适合独立 Web App 的 cookie/session 型认证。插件不会保存 Basic Auth 用户名、密码，也不会让 Worker 给导航请求补 `Authorization`。

### 根目录已经堆了好几个旧备份怎么办

不用手动判断该删哪一份。更新到 2.1.3 或更高版本后再运行一次对应平台的一键安装命令，安装器会先把旧式文件安全复制到 `.cloud-lounge-accelerator/backups/`，确认保存成功后再清理根目录中仅以 `config.yaml.backup-cloud-lounge-` 开头的旧文件：

- 时间最早的一份保存为永久 `config.original.yaml`。
- 最近且内容不同的最多 3 份保存为滚动快照。
- 内容完全相同的备份只留一份。
- `config.yaml.backup-user-created` 等非本插件命名文件完全不碰。

不要把 `config.original.yaml` 当成卸载时的整文件自动恢复点，因为此后用户可能还手动修改过其他配置；它是应急基线。插件正常关闭性能开关时只会修改自己控制的字段。

### 第二次访问仍然慢

- 高级信息中缓存数量为 0：点击“修复插件”。
- 首字节慢：检查服务器区域、线路、TLS、1Panel 反代和上游负载。
- DOM 渲染慢：暂停不需要的大型美化扩展或检查生成超大 HTML 的正则。
- 角色很多：启用 SillyTavern 官方 `performance.lazyLoadCharacters`。

### 拖拽显示“原生”

实际执行顺序仍由原生 ☰ 手柄和 sortable 保存；正则新增的 ↪ 只处理分类归属，不改执行顺序。“生成可切换”代表生成期间的预设开关可以立即保存。如果仍有原生排序异常，请检查 SillyTavern 版本及其他会接管相同列表的扩展。

### 正则修改后旧消息没有变化

编辑已有正则后先等待自动精准刷新；未命中的消息会保持原样。新增、删除、移动、调整顺序或作用范围等高风险操作可能刷新全部已显示消息。需要强制重做所有当前消息时，再点击“重新渲染当前聊天”。

## 十一、安全说明

- 服务端插件不受 SillyTavern 扩展沙箱保护；本项目服务端只提供健康检查、Worker 脚本和三项明确授权的性能配置接口，只有一键安装/更新或用户操作面板开关时才备份并修改对应配置。
- 本插件不缓存 API、账号、聊天、角色、背景、缩略图、用户文件或第三方扩展资源。
- 不要在没有 SillyTavern 账号、Cloudflare Access、Tailscale 或其他可信访问控制时把实例直接暴露到公网。
- “修复插件”和卸载只处理以 `cloud-lounge-static-` 开头的本插件缓存，不处理其他站点数据。
