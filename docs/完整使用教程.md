# 云酒馆加速器完整使用教程

这份教程从“还没安装”开始，覆盖 1Panel Xterminal、Linux、macOS、Windows、更新、验证、使用、卸载和常见错误。

## 一、先看结论

加速器有两个相互独立的部分：

1. **UI 扩展（基础功能）**：提供长聊天渲染减负、官方聊天截断、正则刷新和性能指标。只在酒馆中安装这一部分就能正常使用。
2. **服务端插件（可选增强）**：提供安全的 Service Worker 脚本和健康检查接口，让 UI 扩展额外启用静态资源缓存。

没有服务器权限时，直接只装 UI 即可，面板显示“仅 UI 模式”是正常的。想使用静态资源缓存时，再用一键安装器安装两部分。

### 最快的纯 UI 安装

在 SillyTavern 中打开“扩展 → 安装扩展”，粘贴：

```text
https://github.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator
```

安装后不需要重启服务器。打开“扩展设置 → 云酒馆加速器”，即可使用 1.5.0 的全局前端接管、启动预取、正则合并刷新、自适应首屏、自动旧消息补载、聊天局部高亮、移动端滑动保护和诊断功能。

### 为什么 UI 扩展不能自动补装服务端增强

SillyTavern 里的扩展安装器只会把仓库放进当前用户或全局的 **UI 扩展目录**。这样已经能使用全部前端功能，但浏览器端代码不应该拥有以下权限：

- 往 SillyTavern 根目录的 `plugins/` 写入可执行的服务端代码。
- 自动修改 `config.yaml`。
- 在 `enableServerPlugins: false` 时先启动自己。

如果允许普通网页扩展自动安装服务端代码，任何恶意扩展都可以绕过服务器管理员的确认。因此只有启用可选静态缓存时，才需要在服务器所在环境运行一次安装命令。

**这不等于必须使用 Termux：**

- 安卓本地酒馆：Termux。
- Windows 本地酒馆：PowerShell / Windows Terminal。
- Mac 本地酒馆：系统“终端”。
- VPS / 1Panel：容器 Xterminal 或服务器终端。

运行一键安装命令后，日常使用只需正常打开 SillyTavern，不需要每次进入终端。

安装器还会：

- 自动确认你给的是 SillyTavern 根目录。
- 安装或更新两份 Git 仓库。
- 备份 `config.yaml`。
- 把现有的 `enableServerPlugins` 改为 `true`；不存在时才追加。
- 验证必需文件和配置结果。
- 遇到同名但非 Git 的目录时停止，不覆盖现有文件。

安装器**不会自动重启容器/进程**，因为不同 1Panel 安装的容器名称、Compose 项目和运行方式不同。安装完成后，你只需在 1Panel 点一次“重启”。

## 二、安装前准备

只安装 UI 时，只需要一份能正常运行并允许安装 UI 扩展的 SillyTavern。下面这些是安装完整服务端增强时才需要的：

- 一份已经能正常运行的 SillyTavern。
- Git。SillyTavern 的官方安装通常已经包含/依赖 Git。
- Linux/macOS/Xterminal 需要 `bash`、`curl` 和 SillyTavern 自身使用的 Node.js。
- Windows 需要 Git for Windows 和 PowerShell。
- 云服务器最终使用 HTTPS 主机名访问。没有购买域名时可使用下文的免费 `sslip.io` 地址。同一台本地电脑可使用 `http://localhost:端口` 或 `http://127.0.0.1:端口`。

### 什么是 SillyTavern 根目录

根目录中应该直接看到：

```text
SillyTavern/
├─ server.js
├─ package.json
├─ config.yaml
├─ public/
└─ plugins/       # 可能在第一次安装插件后才出现
```

不要把 `data/default-user` 、`public/scripts` 或安装器仓库本身当成 SillyTavern 根目录。

## 不同部署方式支持表

| 部署方式 | 能否使用 | 安装方式 | 访问地址要求 |
| --- | --- | --- | --- |
| 安卓 Termux 本地酒馆 | 可以 | 在 Termux 中进入 SillyTavern 根目录，运行 Bash 一键命令 | 同一手机用 `http://127.0.0.1:端口` 或 `http://localhost:端口` |
| Windows 本地酒馆 | 可以 | PowerShell 一键命令 | 同一电脑用 `localhost` / `127.0.0.1`；其他设备访问需 HTTPS |
| Mac 本地酒馆 | 可以 | macOS 终端 Bash 一键命令 | 同一电脑用 `localhost` / `127.0.0.1`；其他设备访问需 HTTPS |
| VPS / 1Panel 云酒馆 | 可以 | 容器 Xterminal 或主机挂载目录中运行 Bash 命令 | 对外使用 HTTPS；无自有域名可用 `sslip.io` 免费主机名 |
| Claw 或其他受管云酒馆 | UI 功能可以 | 普通账号安装 UI；有终端/Git 和重启权限时可装完整增强 | UI 无需 HTTPS；静态缓存需 HTTPS |
| 多账号酒馆 | UI 功能可以 | 普通用户安装 UI；服务端增强由管理员决定 | UI 无需 HTTPS；管理员启用缓存时应关闭第三方扩展缓存 |

本插件只优化加载速度，不会改变服务器运营者原有的数据访问权限。在他人管理的多账号酒馆中，插件不能阻止管理员访问服务器文件或用户数据。

### 安卓 Termux 一键安装

如 SillyTavern 安装在 Termux 的 `SillyTavern` 目录：

```bash
cd ~/SillyTavern
curl -fsSL https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.sh | bash
```

安装完成后停止并重新启动 SillyTavern，在同一手机的浏览器中使用：

```text
http://127.0.0.1:你的酒馆端口
```

如手机系统会冻结 Termux，仍需按你原来的方法保持 Termux/SillyTavern 运行；本插件不能阻止安卓系统结束后台进程。

## 三、1Panel Xterminal / Linux 云服务器

### 方式 A：在 SillyTavern 容器终端中执行（推荐）

1. 打开 1Panel。
2. 进入“容器”，找到 SillyTavern 容器。
3. 点“终端”或打开 Xterminal。
4. 先运行：

```bash
pwd
ls
```

如果 `ls` 直接看到 `server.js` 、`package.json` 和 `config.yaml`，当前就是根目录。执行：

```bash
curl -fsSL https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.sh | bash
```

如果你已经知道容器内的 SillyTavern 路径，可以不先 `cd`，直接传入：

```bash
curl -fsSL https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.sh | bash -s -- /path/to/SillyTavern
```

例如实际路径是 `/home/node/app`：

```bash
curl -fsSL https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.sh | bash -s -- /home/node/app
```

### 方式 B：在 1Panel 主机终端中执行

只有 SillyTavern 目录已挂载到主机，而且你知道主机上的真实挂载路径时才使用。将挂载路径传入安装器：

```bash
curl -fsSL https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.sh | bash -s -- /host/path/to/SillyTavern
```

如不确定主机挂载路径，使用方式 A。

### 可选：同时开启角色卡懒加载

角色卡很多时，在命令末尾加：

```bash
curl -fsSL https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.sh | bash -s -- /path/to/SillyTavern --lazy-characters
```

如个别旧扩展与懒加载不兼容，在 `config.yaml` 中把现有的 `lazyLoadCharacters` 改回 `false`。

## 没有自有域名时的 HTTPS 方法

`http://公网IP:端口` 可以打开 SillyTavern，但浏览器不允许它注册 Service Worker。`localhost` 例外只代表正在使用酒馆的这台设备自己，不包含远程 VPS 的公网 IP。

不需要购买域名，可以用 [sslip.io](https://sslip.io/) 提供的免费自动 DNS 主机名。它会把写在主机名中的 IP 自动解析回该 IP。

例如 VPS 地址是：

```text
23.94.194.240
```

则可使用：

```text
23-94-194-240.sslip.io
```

先在浏览器测试下面的地址能否到达原酒馆：

```text
http://23-94-194-240.sslip.io:8000
```

然后在 1Panel 中操作：

1. 进入“网站 → 创建网站 → 反向代理”。
2. 主域名填 `23-94-194-240.sslip.io`。
3. 代理地址填 `http://127.0.0.1:8000`。如 SillyTavern 不在 8000 端口，按实际端口改。
4. 创建网站后，进入“证书”，申请 Let's Encrypt 证书。
5. 证书域名填 `23-94-194-240.sslip.io`，使用 HTTP 验证，开启自动续签。
6. 回到该网站的 HTTPS 设置，选择刚申请的证书，开启 HTTPS 和强制 HTTPS。
7. 服务器防火墙及云安全组放行 TCP 80 和 443。
8. 最终从下面的地址进入，**不再带 `:8000`**：

```text
https://23-94-194-240.sslip.io
```

确认 HTTPS 地址能登录、聊天和打开扩展后，建议从公网防火墙关闭 8000，只保留反向代理的 80/443。

如果 sslip.io 申请证书时遇到 CA 频率限制，可换用 [nip.io](https://nip.io/) 的同类地址：

```text
23-94-194-240.nip.io
```

这种方法不需要你购买或管理域名，但依赖免费 DNS 服务的持续可用性。如将来改用自己的域名，浏览器会把它视为新站点，需重新预热一次。

```bash

```

3. 执行一键安装：

## 五、Windows PowerShell

### 先确认 Git

在 PowerShell 运行：

```powershell
git --version
```

如提示找不到 Git，先安装 Git for Windows，然后关闭并重新打开 PowerShell。

### 一键安装

假设 SillyTavern 在 `C:\SillyTavern`：

```powershell
& ([scriptblock]::Create((irm 'https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.ps1'))) -SillyTavernRoot 'C:\SillyTavern'
```

如已经 `cd` 到 SillyTavern 根目录，可省略路径：

```powershell
& ([scriptblock]::Create((irm 'https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.ps1')))
```

角色卡很多时：

```powershell
& ([scriptblock]::Create((irm 'https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.ps1'))) -SillyTavernRoot 'C:\SillyTavern' -LazyCharacters
```

完成后关闭旧 SillyTavern 窗口/进程，再重新运行 `Start.bat`。

> 如 SillyTavern 运行在 Windows 上的 Docker 容器里，建议进入容器终端并使用 Linux 命令，不要把 Windows 主机路径直接传给容器。

## 七、安装结果是什么

一键安装后，目录应该是：

```text
SillyTavern/
├─ plugins/
│  └─ cloud-lounge-accelerator/                    # 服务端插件
├─ public/scripts/extensions/third-party/
│  └─ cloud-lounge-accelerator/                    # 全局 UI 扩展
├─ config.yaml
└─ config.yaml.backup-cloud-lounge-YYYYMMDD-HHMMSS   # 自动备份
```

`config.yaml` 中会有：

```yaml
enableServerPlugins: true
```

这是正常的“两份仓库”：SillyTavern 对服务端插件和 UI 扩展使用不同加载器和目录。

## 九、日常怎么用

正常启用后不需要每次操作。像平时一样打开酒馆即可。

面板功能：

- **强力前端接管（仅 UI）**：默认开启；统一管理启动、请求、正则、首屏、旧消息、高亮和触摸代理，连续 3 次异常时自动熔断。
- **接管强度**：平衡、强力、极致对应约 8、10、12 ms 单帧预算；不确定时使用默认“强力”。
- **提前显示主界面（仅 UI）**：设置读取完成后释放官方启动遮罩并显示后台初始化提示，下次启动生效。
- **初始化请求预取与去重（仅 UI）**：只在当前网页内短期合并完全相同的角色、头像、背景和扩展模板请求；刷新后自动消失。
- **正则编辑器统一刷新（仅 UI）**：只在正则状态实际保存变化后标记 dirty，连续操作结束后合并成一次局部刷新。
- **自适应首屏消息数（仅 UI）**：根据文本、富标记、设备核心数和内存提示选择 8～30 条；关闭或停用接管时恢复用户原值。
- **自动加载旧消息（仅 UI）**：滚动到顶部附近或点击官方“显示更多”时，每批补入设定条数并保持滚动锚点。
- **聊天代码延迟高亮（仅 UI）**：最近 3 条优先，旧代码进入视口后再处理；可选不高亮或默认折叠旧代码。
- **移动端滑动保护（仅 UI）**：纵向滚动期间阻止左右消息切换误触，明确横向手势保持酒馆原生行为。
- **重美化聊天模式（仅 UI）**：针对消息数量不多、但单条正则 HTML 特别复杂的聊天；一键联动聊天截断与屏幕外渲染减负，关闭后恢复之前的设置。
- **长聊天渲染减负（仅 UI）**：普通模式下达到 20 条后启用，重美化模式下直接启用，并保护最近 5 条消息。
- **长聊天流畅模式（仅 UI）**：兼容手动模式，可选每批 8、10、15、20、30、50 条；自适应首屏开启时由接管器管理。
- **重新应用正则（仅 UI）**：保留聊天 DOM，按“视口内、最近 5 条、其余已显示消息”的顺序分帧刷新；不清编译缓存、不重新请求聊天，再次点击会取消旧任务。
- **平滑加载更早 10 条（仅 UI）**：调用 SillyTavern 官方“显示更多”接口小批量插入旧消息，并锚定可见消息保持滚动位置。
- **完整重载（高级，仅 UI）**：清理正则编译缓存并完整重载当前聊天，仅在局部刷新无效或正则状态异常时使用。
- **聊天加载诊断（仅 UI）**：显示聊天请求、传输量、显示/总消息数、DOM 节点、美化复杂度、首批内容、前端处理估算、完整加载与最长主线程阻塞。
- **启用静态资源缓存（服务端增强）**：关闭时会卸载本项目的 Service Worker 并清理程序缓存。
- **自动预热当前版本一次（服务端增强）**：默认关闭，只在酒馆启动完成、页面可见、网络允许且浏览器空闲时运行。
- **缓存第三方扩展**：个人单账号酒馆可开启；同一域名下有多个账号时保持关闭。
- **立即预热**：新安装大量扩展后可点一次。
- **清空并重建**：页面大改、扩展更新后如遇到旧样式，点一次。
- **刷新缓存状态**：按需读取缓存数量和命中数，不在启动阶段反复枚举。
- **删除本机缓存**：注销 Worker 并清理静态缓存，不影响纯 UI 功能，也不删除聊天、角色卡、设置或插件文件。

它不会加速 AI 回复生成；主要加速“打开网址到酒馆可用”的程序文件加载。

### 正则美化为什么会卡

SillyTavern 的正则编辑器、列表和调试器使用多份按需加载的 HTML/CSS 模板。完整增强模式会在 `APP_READY` 后且浏览器空闲时预热这些模板，后台并发数限制为 3，不与首页字体、美化和聊天渲染抢网络；纯 UI 模式不执行网络预热。

但正则把一条消息替换成大量折叠块、选项、复杂 CSS 或上万个 DOM 节点时，打开该块必须由当前设备的浏览器执行布局和绘制。这与 VPS 下载速度不是一回事，Service Worker 也无法把这部分计算放到服务器。

建议顺序：

1. 个人单账号酒馆打开“缓存第三方扩展”。
2. 正则和折叠美化很多时打开“长聊天渲染减负”。
3. 在 SillyTavern 的用户设置中设置合理的“聊天截断/每次显示消息数”，不要一次渲染整个超长聊天。
4. 新正则保存后旧消息没更新，点“重新应用正则”；它会原地分帧刷新，进度区可随时取消。只有局部刷新无效时才使用“完整重载（高级）”。
5. 如仍无效，检查该正则的“影响位置”、“仅格式化显示”、最小/最大深度、禁用状态，以及角色/预设正则是否已授权启用。

### 聊天加载诊断怎么看

- **聊天请求高**：优先检查服务器、反向代理、线路和聊天文件大小。
- **聊天请求低，但前端处理估算高**：主要时间花在 JSON 解析、正则、Markdown、HTML 清洗、DOM 创建或其他扩展的后处理。
- **聊天 DOM 节点很多**：开启“重美化聊天模式”，将每批消息调到 10、15 或 20 条，并检查正则替换内容是否反复生成大量嵌套节点、阴影或模糊效果。
- **最长主线程阻塞高**：表示浏览器曾连续至少 50 ms 无法响应输入；数百毫秒以上通常会产生明显空白或卡顿。
- **聊天请求和前端处理都低但仍卡**：暂停其他会监听聊天切换的扩展做对比。

“前端处理估算”不是单独的正则耗时，因此只能测量聊天响应完成到官方 `CHAT_CHANGED` 之间的综合前端时间。1.5.0 不替换正则或 Markdown 引擎；它只对 `#chat` 内高亮调用和官方“显示更多”入口建立可恢复代理，聊天外代码高亮及底层消息生成仍由 SillyTavern 原生实现。

### 接管异常、安全模式与原生回退

- 临时安全进入：在酒馆地址后添加 `?cla-safe=1`，例如 `https://你的域名/?cla-safe=1`。本次页面会跳过全部前端接管。
- 连续出现 3 次接管异常：总开关自动关闭，`fetch`、高亮、滚动、触摸监听、Observer 和计时器都会恢复。
- 聊天区域在切换后持续空白 8 秒：插件自动调用官方 `reloadCurrentChat()` 完整读取作为一次回退。
- “暂停当前前端任务”：取消统一调度队列和正在进行的分帧任务，不会删除聊天。
- “恢复酒馆原生流程”：关闭总开关并立即拆除所有代理；需要时可重新开启。
- “完整重载（高级）”：只有局部刷新无效或正则状态异常时使用，执行前会要求确认。

### 对照 SillyTavern 1.18.0 源码后的加载边界

| 路径/资源 | 本插件的处理 | 原因 |
| --- | --- | --- |
| `/script.js`、`/style.css`、`/lib.js` | 缓存 | 首页核心程序文件 |
| `/scripts/`、`/css/`、`/lib/`、`/locales/` | 按实际请求缓存 | SillyTavern 模块、界面、依赖和语言包 |
| `/webfonts/`、`/img/`、`/sounds/` | 按实际请求缓存 | 字体、程序图标和提示音 |
| `/scripts/extensions/regex/*.html` | 空闲时主动预热 | 正则编辑器、列表、调试器是按需请求的模板 |
| `/scripts/templates/theme*.html` | 空闲时主动预热 | 降低首次打开主题相关对话框的等待 |
| `/scripts/extensions/third-party/` | 只在个人明确开启后缓存 | 第三方美化/扩展的 JS、CSS 和静态模板 |
| `/api/`、`/characters/`、`/backgrounds/`、`/thumbnail`、`/user/` | **永不进入本插件缓存** | 包含设置、正则内容、聊天、角色卡或用户资源 |
| 根页面 `/` | 每次走网络 | 保证登录状态和 SillyTavern 版本变更不被旧页面阻塞 |

“正则保存后不生效”不能通过缓存 `/api/settings/save` 解决：那样反而可能留住旧设置。本项目只预热正则界面的静态模板，正则内容始终实时从 SillyTavern 内存/服务端设置读取。

## 十、更新

最简单的更新方式是重新运行原来的一键安装命令。安装器发现目录已是 Git 仓库时，会对服务端和 UI 两份执行安全的 `git pull --ff-only`。

Linux/macOS/Xterminal：

```bash
curl -fsSL https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.sh | bash -s -- /path/to/SillyTavern
```

Windows：

```powershell
& ([scriptblock]::Create((irm 'https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.ps1'))) -SillyTavernRoot 'C:\SillyTavern'
```

更新完成后重启 SillyTavern。

## 十一、卸载

1. 在酒馆“扩展设置”中先关闭“启用静态资源缓存”，让它清理 Service Worker 和缓存。
2. 停止 SillyTavern。
3. 备份后删除：

```text
plugins/cloud-lounge-accelerator/
public/scripts/extensions/third-party/cloud-lounge-accelerator/
```

4. 只有确定没有其他服务端插件时，才可以把 `enableServerPlugins` 改回 `false`。
5. 重启 SillyTavern。

## 十二、常见错误

### “这不是 SillyTavern 根目录”

你传入的目录不对。正确目录必须直接包含 `server.js`、`package.json` 和 `config.yaml`。

### `curl: command not found`

容器缺少 curl。可以在 1Panel 主机终端使用挂载路径执行，或先下载 `scripts/install.sh` 后上传到容器并执行。

### `git: command not found`

当前环境没有 Git。请在容器/系统中安装 Git，或改用 README 中的手动安装方式。

### “目录已存在，但不是 Git 仓库”

你以前可能手动解压过同名目录。安装器为了不覆盖文件会停止。先将旧目录重命名保留，再重新运行安装器。

### 显示“仅 UI 模式”

如果你只安装了 UI 扩展，这是正常状态。长聊天优化、聊天截断、正则刷新和性能指标仍然可以使用。

如果你希望启用静态资源缓存，再检查：

- 确认已重启 SillyTavern。
- 确认 `config.yaml` 中是 `enableServerPlugins: true`。
- 搜索日志里的 `cloud-lounge-accelerator` 和 `Plugin loading failed`。
- 确认服务端目录中存在 `server/index.js`。

### “加速服务响应超时”

如同时能看到“本次命中”大于 0，说明 Service Worker 和静态缓存已经在工作，超时发生在预热/统计通信阶段。

`1.0.1` 已修复慢服务器上的两个问题：预热改为复用浏览器已有 HTTP 缓存，且已命中的数百个资源不再每次同时向服务器重新校验。请重新运行一键安装命令更新两份仓库，然后重启 SillyTavern。

如更新后仍超时：

1. 重新打开页面，等待面板状态恢复为“完整模式”。
2. 只点一次“清空并重建”，不要连续点击。
3. 检查首字节（TTFB）。本地酒馆如出现数秒以上 TTFB，说明 SillyTavern 进程/设备本身卡顿；云酒馆则需继续比较服务器内网和公网域名。

在 1Panel 容器内测试 SillyTavern 上游（把端口改成实际端口）：

```bash
curl -o /dev/null -sS -w 'connect=%{time_connect}s ttfb=%{time_starttransfer}s total=%{time_total}s\n' http://127.0.0.1:8000/
```

在你的电脑终端测试公网域名：

```bash
curl -o /dev/null -sS -w 'connect=%{time_connect}s ttfb=%{time_starttransfer}s total=%{time_total}s\n' https://你的酒馆域名/
```

- 容器内快、公网慢：主要查 1Panel 反代、TLS、服务器地区和网络线路。
- 容器内也慢：主要查 SillyTavern 进程、CPU/内存、磁盘和是否存在休眠/冷启动。

### “需要 HTTPS”

- 云服务器上的 `http://公网IP:端口` 不能注册 Service Worker。
- 局域网中从其他设备打开 `http://192.168.x.x:端口` 也通常不可以。
- 同一台电脑的 `http://localhost:端口` 和 `http://127.0.0.1:端口` 可以。
- 云酒馆请在 1Panel 中绑定主机名、申请证书并开启 HTTPS。没有购买域名时，按本教程的 `sslip.io` 方法配置。

### 保存新正则后，旧消息没有加载新效果

1. 先确认保存时没有语法错误提示，且正则不是“禁用”。
2. 确认“影响位置”包含 AI 输出/用户输入中你希望处理的一项。
3. 角色正则和预设正则需要打开对应的允许开关。
4. 在“云酒馆加速器”中点“重新应用正则”。它会保留当前聊天，优先处理屏幕内消息，再分帧刷新其他已显示消息；默认不会清理缓存或重新请求聊天。
5. 局部刷新仍无效时，使用“完整重载（高级）”。它会清理正则编译缓存并让 SillyTavern 重载当前聊天，执行前会二次确认，但不会删除聊天数据。
6. 仍无效时，用 SillyTavern 正则调试器把一小段原文粘贴进去，确认查找表达式确实命中。

### 安装后第一次没感觉变快

正常。第一次访问在建立缓存，第二次及以后才是主要加速场景。如状态中资源数为 0，点“立即预热”。

### 如何恢复 `config.yaml`

安装器会在同目录生成：

```text
config.yaml.backup-cloud-lounge-YYYYMMDD-HHMMSS
```

停止 SillyTavern 后，将所需时间的备份复制回 `config.yaml`，再重启。
