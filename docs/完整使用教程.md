# 云酒馆加速器完整使用教程

这份教程从“还没安装”开始，覆盖 1Panel Xterminal、Linux、macOS、Windows、更新、验证、使用、卸载和常见错误。

## 一、先看结论

加速器有两个必需部分：

1. **服务端插件**：提供安全的 Service Worker 脚本和健康检查接口。
2. **UI 扩展**：在浏览器中注册 Service Worker、预热资源并显示设置面板。

两者不是二选一。一键安装器会同时安装它们，所以你不用再手工复制两遍。

### 为什么不能只在 SillyTavern 里点“安装扩展”

SillyTavern 里的扩展安装器只会把仓库放进当前用户或全局的 **UI 扩展目录**。这是浏览器端代码，它不应该拥有以下权限：

- 往 SillyTavern 根目录的 `plugins/` 写入可执行的服务端代码。
- 自动修改 `config.yaml`。
- 在 `enableServerPlugins: false` 时先启动自己。

如果允许普通网页扩展自动安装服务端代码，任何恶意扩展都可以绕过服务器管理员的确认。因此首次需要在服务器所在环境运行一次安装命令。

**这不等于必须使用 Termux：**

- 安卓本地酒馆：Termux。
- Windows 本地酒馆：PowerShell / Windows Terminal。
- Mac 本地酒馆：系统“终端”。
- VPS / 1Panel：容器 Xterminal 或服务器终端。

运行一键安装命令后，日常使用只需正常打开 SillyTavern，不需要每次进入终端。

安装器还会：

- 自动确认你给的是 SillyTavern 根目录。
- 安装或更新两份 Git 仓库。
- 备份 `config.yaml`。
- 把现有的 `enableServerPlugins` 改为 `true`；不存在时才追加。
- 验证必需文件和配置结果。
- 遇到同名但非 Git 的目录时停止，不覆盖现有文件。

安装器**不会自动重启容器/进程**，因为不同 1Panel 安装的容器名称、Compose 项目和运行方式不同。安装完成后，你只需在 1Panel 点一次“重启”。

## 二、安装前准备

需要：

- 一份已经能正常运行的 SillyTavern。
- Git。SillyTavern 的官方安装通常已经包含/依赖 Git。
- Linux/macOS/Xterminal 需要 `bash`、`curl` 和 SillyTavern 自身使用的 Node.js。
- Windows 需要 Git for Windows 和 PowerShell。
- 云服务器最终使用 HTTPS 域名访问。同一台本地电脑可使用 `http://localhost:端口` 或 `http://127.0.0.1:端口`。

### 什么是 SillyTavern 根目录

根目录中应该直接看到：

```text
SillyTavern/
├─ server.js
├─ package.json
├─ config.yaml
├─ public/
└─ plugins/       # 可能在第一次安装插件后才出现
```

不要把 `data/default-user` 、`public/scripts` 或安装器仓库本身当成 SillyTavern 根目录。

## 不同部署方式支持表

| 部署方式 | 能否使用 | 安装方式 | 访问地址要求 |
| --- | --- | --- | --- |
| 安卓 Termux 本地酒馆 | 可以 | 在 Termux 中进入 SillyTavern 根目录，运行 Bash 一键命令 | 同一手机用 `http://127.0.0.1:端口` 或 `http://localhost:端口` |
| Windows 本地酒馆 | 可以 | PowerShell 一键命令 | 同一电脑用 `localhost` / `127.0.0.1`；其他设备访问需 HTTPS |
| Mac 本地酒馆 | 可以 | macOS 终端 Bash 一键命令 | 同一电脑用 `localhost` / `127.0.0.1`；其他设备访问需 HTTPS |
| VPS / 1Panel 云酒馆 | 可以 | 容器 Xterminal 或主机挂载目录中运行 Bash 命令 | 对外访问使用 HTTPS 域名 |
| Claw 或其他受管云酒馆 | 视权限而定 | 必须同时拥有持久文件目录、终端/Git 和重启权限 | 需 HTTPS；如只给酒馆账号而不给服务器权限，不能安装服务端部分 |
| 商业多账号酒馆 | 技术上可以，需管理员 | 由服务器管理员安装；普通用户无法自行安装服务端插件 | 需 HTTPS；应保持“缓存第三方扩展”关闭 |

本插件只优化加载速度，不会改变服务器运营者原有的数据访问权限。在他人管理的商业酒馆中，插件不能阻止管理员访问服务器文件或用户数据。

### 安卓 Termux 一键安装

如 SillyTavern 安装在 Termux 的 `SillyTavern` 目录：

```bash
cd ~/SillyTavern
curl -fsSL https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.sh | bash
```

安装完成后停止并重新启动 SillyTavern，在同一手机的浏览器中使用：

```text
http://127.0.0.1:你的酒馆端口
```

如手机系统会冻结 Termux，仍需按你原来的方法保持 Termux/SillyTavern 运行；本插件不能阻止安卓系统结束后台进程。

## 三、1Panel Xterminal / Linux 云服务器

### 方式 A：在 SillyTavern 容器终端中执行（推荐）

1. 打开 1Panel。
2. 进入“容器”，找到 SillyTavern 容器。
3. 点“终端”或打开 Xterminal。
4. 先运行：

```bash
pwd
ls
```

如果 `ls` 直接看到 `server.js` 、`package.json` 和 `config.yaml`，当前就是根目录。执行：

```bash
curl -fsSL https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.sh | bash
```

如果你已经知道容器内的 SillyTavern 路径，可以不先 `cd`，直接传入：

```bash
curl -fsSL https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.sh | bash -s -- /path/to/SillyTavern
```

例如实际路径是 `/home/node/app`：

```bash
curl -fsSL https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.sh | bash -s -- /home/node/app
```

### 方式 B：在 1Panel 主机终端中执行

只有 SillyTavern 目录已挂载到主机，而且你知道主机上的真实挂载路径时才使用。将挂载路径传入安装器：

```bash
curl -fsSL https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.sh | bash -s -- /host/path/to/SillyTavern
```

如不确定主机挂载路径，使用方式 A。

### 可选：同时开启角色卡懒加载

角色卡很多时，在命令末尾加：

```bash
curl -fsSL https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.sh | bash -s -- /path/to/SillyTavern --lazy-characters
```

如个别旧扩展与懒加载不兼容，在 `config.yaml` 中把现有的 `lazyLoadCharacters` 改回 `false`。

## 四、macOS 本地 SillyTavern

1. 打开“终端”。
2. 使用 `cd` 进入 SillyTavern 根目录。路径含空格时用引号：

```bash
cd '/Users/你的用户名/path with spaces/SillyTavern'
```

3. 执行一键安装：

```bash
curl -fsSL https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.sh | bash
```

4. 安装完成后停止并重新启动 SillyTavern。
5. 在同一台 Mac 上可直接使用 `http://localhost:端口`；从手机/其他电脑通过局域网 IP 访问时，仍需 HTTPS 才能启用 Service Worker。

## 五、Windows PowerShell

### 先确认 Git

在 PowerShell 运行：

```powershell
git --version
```

如提示找不到 Git，先安装 Git for Windows，然后关闭并重新打开 PowerShell。

### 一键安装

假设 SillyTavern 在 `C:\SillyTavern`：

```powershell
& ([scriptblock]::Create((irm 'https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.ps1'))) -SillyTavernRoot 'C:\SillyTavern'
```

如已经 `cd` 到 SillyTavern 根目录，可省略路径：

```powershell
& ([scriptblock]::Create((irm 'https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.ps1')))
```

角色卡很多时：

```powershell
& ([scriptblock]::Create((irm 'https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.ps1'))) -SillyTavernRoot 'C:\SillyTavern' -LazyCharacters
```

完成后关闭旧 SillyTavern 窗口/进程，再重新运行 `Start.bat`。

> 如 SillyTavern 运行在 Windows 上的 Docker 容器里，建议进入容器终端并使用 Linux 命令，不要把 Windows 主机路径直接传给容器。

## 六、如果不想使用“管道一键命令”

`curl ... | bash` 和动态 PowerShell 命令会下载并立即执行仓库中的安装器。你可以先下载、阅读，再执行。

Linux/macOS：

```bash
curl -fLo cloud-lounge-install.sh https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.sh
less cloud-lounge-install.sh
bash cloud-lounge-install.sh /path/to/SillyTavern
```

Windows PowerShell：

```powershell
Invoke-WebRequest 'https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.ps1' -OutFile '.\cloud-lounge-install.ps1'
Get-Content '.\cloud-lounge-install.ps1'
powershell -ExecutionPolicy Bypass -File '.\cloud-lounge-install.ps1' -SillyTavernRoot 'C:\SillyTavern'
```

## 七、安装结果是什么

一键安装后，目录应该是：

```text
SillyTavern/
├─ plugins/
│  └─ cloud-lounge-accelerator/                    # 服务端插件
├─ public/scripts/extensions/third-party/
│  └─ cloud-lounge-accelerator/                    # 全局 UI 扩展
├─ config.yaml
└─ config.yaml.backup-cloud-lounge-YYYYMMDD-HHMMSS   # 自动备份
```

`config.yaml` 中会有：

```yaml
enableServerPlugins: true
```

这是正常的“两份仓库”：SillyTavern 对服务端插件和 UI 扩展使用不同加载器和目录。

## 八、重启与验证

### 1Panel / Docker

1. 返回 1Panel 的容器页面。
2. 找到 SillyTavern 容器。
3. 点“重启”。
4. 打开容器日志，搜索：

```text
cloud-lounge-accelerator
```

正常时应看到类似：

```text
Initializing plugin from .../plugins/cloud-lounge-accelerator/server/index.js
```

### 酒馆页面

1. 用 HTTPS 域名打开云酒馆；同机本地可用 `localhost` / `127.0.0.1`。
2. 进入“扩展设置 → 云酒馆加速器”。
3. 状态应显示：

```text
已启用 · N 个本地资源
```

4. 如 N 为 0，点“立即预热”。
5. 第一次成功进入是建立缓存，关闭页面后再打开一次，才是主要对比。

## 九、日常怎么用

正常启用后不需要每次操作。像平时一样打开酒馆即可。

面板功能：

- **启用本地加速**：总开关。关闭时会卸载本项目的 Service Worker 并清理程序缓存。
- **自动预热当前安装**：根据当前页面真实请求收集核心资源。建议保持开启。
- **缓存第三方扩展**：个人单账号酒馆可开启；同一域名下有多个账号时保持关闭。
- **立即预热**：新安装大量扩展后可点一次。
- **清空并重建**：页面大改、扩展更新后如遇到旧样式，点一次。
- **删除本机加速**：弹出确认后，注销当前浏览器中的加速 Service Worker，清理本插件的全部本地缓存并关闭加速。它不会删除聊天、角色卡、设置、UI 扩展或服务端插件文件；以后可重新打开“启用本地加速”。

它不会加速 AI 回复生成；主要加速“打开网址到酒馆可用”的程序文件加载。

## 十、更新

最简单的更新方式是重新运行原来的一键安装命令。安装器发现目录已是 Git 仓库时，会对服务端和 UI 两份执行安全的 `git pull --ff-only`。

Linux/macOS/Xterminal：

```bash
curl -fsSL https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.sh | bash -s -- /path/to/SillyTavern
```

Windows：

```powershell
& ([scriptblock]::Create((irm 'https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.ps1'))) -SillyTavernRoot 'C:\SillyTavern'
```

更新完成后重启 SillyTavern。

## 十一、卸载

1. 在酒馆“扩展设置”中先关闭“启用本地加速”，让它清理 Service Worker 和缓存。
2. 停止 SillyTavern。
3. 备份后删除：

```text
plugins/cloud-lounge-accelerator/
public/scripts/extensions/third-party/cloud-lounge-accelerator/
```

4. 只有确定没有其他服务端插件时，才可以把 `enableServerPlugins` 改回 `false`。
5. 重启 SillyTavern。

## 十二、常见错误

### “这不是 SillyTavern 根目录”

你传入的目录不对。正确目录必须直接包含 `server.js`、`package.json` 和 `config.yaml`。

### `curl: command not found`

容器缺少 curl。可以在 1Panel 主机终端使用挂载路径执行，或先下载 `scripts/install.sh` 后上传到容器并执行。

### `git: command not found`

当前环境没有 Git。请在容器/系统中安装 Git，或改用 README 中的手动安装方式。

### “目录已存在，但不是 Git 仓库”

你以前可能手动解压过同名目录。安装器为了不覆盖文件会停止。先将旧目录重命名保留，再重新运行安装器。

### “服务端插件未就绪”

- 确认已重启 SillyTavern。
- 确认 `config.yaml` 中是 `enableServerPlugins: true`。
- 搜索日志里的 `cloud-lounge-accelerator` 和 `Plugin loading failed`。
- 确认服务端目录中存在 `server/index.js`。

### “加速服务响应超时”

如同时能看到“本次命中”大于 0，说明 Service Worker 和静态缓存已经在工作，超时发生在预热/统计通信阶段。

`1.0.1` 已修复慢服务器上的两个问题：预热改为复用浏览器已有 HTTP 缓存，且已命中的数百个资源不再每次同时向服务器重新校验。请重新运行一键安装命令更新两份仓库，然后重启 SillyTavern。

如更新后仍超时：

1. 重新打开页面，等待面板状态恢复为“已启用”。
2. 只点一次“清空并重建”，不要连续点击。
3. 检查首字节（TTFB）。本地酒馆如出现数秒以上 TTFB，说明 SillyTavern 进程/设备本身卡顿；云酒馆则需继续比较服务器内网和公网域名。

在 1Panel 容器内测试 SillyTavern 上游（把端口改成实际端口）：

```bash
curl -o /dev/null -sS -w 'connect=%{time_connect}s ttfb=%{time_starttransfer}s total=%{time_total}s\n' http://127.0.0.1:8000/
```

在你的电脑终端测试公网域名：

```bash
curl -o /dev/null -sS -w 'connect=%{time_connect}s ttfb=%{time_starttransfer}s total=%{time_total}s\n' https://你的酒馆域名/
```

- 容器内快、公网慢：主要查 1Panel 反代、TLS、服务器地区和网络线路。
- 容器内也慢：主要查 SillyTavern 进程、CPU/内存、磁盘和是否存在休眠/冷启动。

### “需要 HTTPS”

- 云服务器上的 `http://公网IP:端口` 不能注册 Service Worker。
- 局域网中从其他设备打开 `http://192.168.x.x:端口` 也通常不可以。
- 同一台电脑的 `http://localhost:端口` 和 `http://127.0.0.1:端口` 可以。
- 云酒馆请在 1Panel 中绑定域名、申请证书并开启 HTTPS。

### 安装后第一次没感觉变快

正常。第一次访问在建立缓存，第二次及以后才是主要加速场景。如状态中资源数为 0，点“立即预热”。

### 如何恢复 `config.yaml`

安装器会在同目录生成：

```text
config.yaml.backup-cloud-lounge-YYYYMMDD-HHMMSS
```

停止 SillyTavern 后，将所需时间的备份复制回 `config.yaml`，再重启。
