# 云酒馆加速器 2.1.43

让云端 SillyTavern 打开更快、长聊天更流畅，同时避免重复接管预设、正则和世界书的原生交互。安装后大部分功能都会自动工作，不需要手动调整复杂参数。

2.1.43 保留滑动和流式生成时的毛玻璃外观：加速器不再临时关闭气泡模糊，也不覆盖 iMessage 美化样式。流式预览节流、滑动时降低预览频率、慢渲染后的恢复间隔、聊天分页和其他加速保持生效。

2.1.42 简化正则操作反馈：移除插在行内和按钮旁的“正在保存顺序 / 正在保存 / 正在删除”。拖动后立即显示新位置，并可继续拖动；编辑点击保存后立即关窗，删除确认后立即移走记录，后台依次写入。失败时才提示，恢复未保存的顺序或未删除的规则；编辑失败会保留草稿并在合适时恢复编辑窗口。

2.1.41 可直接在合集里拖动排序，无需切换视图：规则左侧统一使用 `⠿` 六点手柄，拖到同组规则的上半部/下半部即放到其前/后，拖到其他合集标题或浮动目标则归组；勾选的同组规则可一起排序，跨组勾选仍可批量归组。合集标题左侧也有手柄，可调整合集显示位置。组内排序保存实际规则执行顺序，其他合集的规则保留原槽位；合集标题位置单独保存为显示偏好。

2.1.40 补充分组识别：`01 | 社交动态 | 正文`、`00b | iMessage | 会话视角` 会按第二段自动归入“社交动态”“iMessage”，兼容全角竖线，原有括号分组和手动归组继续保留。在“全局正则、预设正则、局部正则”的列表上方可直接点“新建分组”，生成一个 0 条的“新分组”并立即改名，重名时自动编号；取消改名会保留空组，可继续拖入规则，无需先打开管理面板。

2.1.39 新增聊天记录批量删除：打开原生“聊天记录”窗口 → 点“批量操作” → 勾选聊天，或点“全选当前结果” → “删除所选”，统一确认一次即可。支持角色聊天和群聊，显示已选数量及删除进度；搜索后清空选择，当前打开的聊天会标记并排除，需先切换到其他聊天才能批量删除它。请求失败时停止后续删除，保留失败与未处理项，并提示实际完成数量。该功能随“界面操作优化”启用，无需安装服务端。

2.1.38 修复慢渲染时连续重渲染的问题：从原生预览完成后再留出恢复间隔。触屏生成及普通滑动期间临时减轻气泡毛玻璃开销，生成结束、滚动停稳后恢复；不改变消息高度、阅读位置和正文。批量删正则按范围合并保存，编辑保存有处理中提示和防重复提交。新增 ↪ 归组手柄，支持拖到分组标题或浮动目标；快速划选会补齐中间行。等价重复的选择、归组逻辑及公共样式已合并，原正则内容与执行顺序保留。验证与报告边界见[2.1.38 排查](docs/生成与正则操作排查-2.1.38.md)。

2.1.37 支持自定义正则分组：分组标题旁点“改名”；打开“整理正则 → 管理分组”可新建空组，勾选正则后选择目标组并点击“将已选正则移入分组”，也可移回未分类。分类随酒馆设置保存，按全局、当前预设与当前角色分别记录，不修改原始正则名称、内容、开关或执行顺序。整理框改为按实际侧栏宽度自动排版，兼容桌面窄面板、手机、大字体和现有美化；长组名换行，长规则名省略显示并提供完整名称提示。

2.1.36 针对生成中滑动时的停顿减少整段消息的重复渲染：“聊天与重美化优化”开启后，触屏流式预览上限为 20 次/秒、桌面为 30 次/秒，实际滑动期间临时降至最多 8 次/秒；格式化耗时较长时自动留出更多响应时间。最终正文立即完整渲染，生成接收、原生保存及其他扩展的 token 事件继续照常处理；不改写或保存原生帧率、淡入设置。此功能在 `APP_READY` 后加载，停止、切换聊天或关闭优化时恢复原生方法。检查结果与录屏证据边界见[生成滚动排查](docs/生成滚动排查-2.1.36.md)。

2.1.35 减少生成与点击期间的额外工作：流式生成时暂停插件代码扫描，弹窗监听跳过聊天内容的子树搜索；普通点按不再同步读取多层样式、命中栈和输入框布局。代码高亮保留原复制按钮，选字或按住消息时暂缓处理，超过 20,000 字符的代码保持原文显示并跳过语法解析。此版修复插件自身可确认的开销，不代表已确认所有页面/应用退出的原因，详见[报告排查与验证边界](docs/生成与交互排查-2.1.35.md)。

2.1.34 增加电脑/手机预设防误拖：开启“界面操作优化”后，只有左侧 ☰ 手柄可以排序，至少按住 150ms 并移动 10px 才启动拖拽；点击名称、开关或编辑按钮、从这些区域滑动翻页都不会触发排序。触屏开关也会区分点按与滑动，防止翻页时误切换。排序与保存继续使用酒馆原生实现。

2.1.29 移除显示调整和正则回退中的额外聊天重读，保留重要交互异常并纠正设置下载计时。官方聊天加载/保存风险、原生重复设置读取及空白现场的已确认与未确认边界，见[安全与启动审查](docs/安全与启动审查-2.1.29.md)。

2.1.30 修正设置请求下限漏计和自定义图标已完整接收 click 时的传播误报；该审查记录追加了 1.18.0 release 及电脑/手机实测对照。

2.1.31 移除所有设备上的提前撤罩与加速器强制恢复欢迎页，补充扩展设置事件和 APP_READY 订阅回调的分阶段计时；具体边界见[本次启动与聊天审查](docs/启动与聊天审查-2.1.31.md)。

2.1.32 缩减启动依赖：激活前本仓库脚本从 25 个、约 246KB 减到 7 个、约 80KB（未压缩源代码）；交互、正则整理、设置面板和缓存模块改为原生 `APP_READY` 后加载，聊天显示条数仍提前设置。本插件设置迁移保存延到就绪后，单纯版本更新不上传完整设置；没有增加诊断项。这减少插件自身的启动负担，实际耗时仍取决于其余扩展、服务器和网络。

2.1.33 继续减少启动下载：将 2.1.32 的启动依赖打包压缩，首次激活从 7 个本插件脚本、约 80KB 减为 2 个、约 43KB（HTTP 压缩前）；其余功能仍在原生 `APP_READY` 后加载，合并为一个延迟文件。发布文件随仓库提供，安装和更新无需构建；本版没有增加诊断项，也没有调整功能启动顺序。

## 一键安装完整版本

一键安装会同时安装界面扩展和服务端加速。安装完成后，请手动重启 SillyTavern。

一键安装的界面扩展属于**全局扩展**，供所有酒馆账号使用。启用多用户后，只有酒馆管理员账号能在扩展管理器里更新它；普通账号仍可更新自己安装的个人扩展。因此“其他插件能更新，加速器提示没有更新全局扩展的权限”通常是安装范围不同。保持多用户开启，切换到管理员账号更新即可；需要同时更新服务端时，重新运行下面的安装命令。

### VPS / 1Panel XTerminal

```bash
cd /root/SillyTavern
curl -fsSL https://raw.githubusercontent.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator/main/scripts/install.sh | bash
```

### Android / Termux

```bash
pkg install curl -y
cd ~/SillyTavern
```

### Mac / 终端

```bash

```


这些命令同时适用于首次安装和以后更新。路径与教程不同时，只修改 `cd` 后的路径或 Windows 的 `-SillyTavernRoot`；安装完成后重启 SillyTavern。

更多安装、更新、卸载、1Panel 和 HTTPS 步骤见 [完整使用教程](docs/完整使用教程.md)。

普通安装/更新现在会开启聊天保存上传压缩；Keep-Alive 和角色卡懒加载仍保持原值。需要在安装时直接开启后两项时，可单独使用 `--keep-alive`、`--lazy-characters`，或用 `--fast-start` 同时开启：

```bash

```

Keep-Alive 在部分网络环境可能引发 `ECONNRESET` 或连接中断；角色卡懒加载可能不兼容旧扩展，并会让高级模糊搜索只按角色名搜索。两项都要重启 SillyTavern 才生效。

## 主要功能

### 页面加载加速

- 只缓存 SillyTavern 的脚本、样式、字体、语言包、图片和声音等程序资源。
- 完成登录后才检查版本并启动页面缓存，不会干扰登录过程。
- 所有设备均由 SillyTavern 原生流程关闭启动遮罩，加速器不再于 `SETTINGS_LOADED` 提前关闭；不自动强制恢复欢迎页，避免额外异步任务干扰角色切换。
- 角色库、头像与背景库读取保持原生响应，不为请求复用保留额外响应流；云端设置读取延后到 `APP_READY`，合并重复刷新，减少启动阶段的内存和请求竞争。
- 反向代理已提供至少 5 分钟的有效浏览器缓存时，自动注销 Worker 并直通原生 HTTP/disk cache，避免静态资源额外等待 Worker 冷启动；没有可靠缓存头时继续使用 Worker。
- UI 与服务端插件版本不一致时会自动注销旧 Worker 并停止页面缓存，防止服务端旧代码被反复装回。
- 检测到 iOS 主屏幕独立 Web App 与 HTTP Basic Auth 同时使用时，会自动注销并停用根作用域 Worker，保留启动、聊天、正则和交互优化。
- 当前版本在浏览器空闲、页面可见且网络允许时只自动预热一次。
- 扩展安装、更新或删除后，自动清理旧的程序缓存。
- 启动阶段短时间合并完全相同的扩展发现和模板请求；角色、头像、背景请求保持原生通路。

登录兼容：

- 不接管页面跳转，兼容 Basic Auth、登录页和反向代理认证。
- 登录失败、无权访问、认证提示和跳转响应不会被缓存。
- API、聊天、角色卡、背景、缩略图、用户文件和第三方扩展资源不会被缓存。

### 聊天与重美化优化

- 一键安装/更新会开启 SillyTavern 官方请求 gzip：超过 256KB 的聊天保存先在浏览器压缩再上传，并取消官方默认 8MB 压缩上限，15MB 等大聊天也会生效；压缩超时会回退原始保存。
- 保存语义仍是官方的完整聊天覆盖，服务端完整性检查和聊天备份保持不变。插件不使用自定义增量协议，避免编辑旧楼、删除消息、切换 Swipe、元数据变化或多端并发时损坏 JSONL。
- 打开或切换大聊天时不再复制并二次解析完整响应；复杂度判断直接复用 SillyTavern 已解析的聊天数组，降低手机浏览器的峰值内存和主线程停顿。
- 打开任何角色聊天时默认只先显示最后 5 条；可在加速器的“聊天显示”页自由调整为 1–50 条，下次打开聊天时应用，调整数量不会重新读取当前聊天。
- 切换聊天后的首秒布局变化会通过 SillyTavern 官方滚动接口继续贴住最后一条；一旦用户触碰或加载历史消息便立即停止校准。
- 点击“显示更多”时由 SillyTavern 原生流程按同一页数补载旧消息并保持阅读位置；插件会先登记当前会话，不会把这次补载误判成首次进入而跳到底部。
- 最近代码优先高亮；旧代码进入视口后再处理，并默认以可点击预览形式折叠。
- 完整 HTML 源码即使没有 `language-html` 类名也会跳过语法高亮，避免在最终美化出现前重复处理大量节点。
- 流式生成和停止清理期间暂停代码块扫描，等 SillyTavern 真正解锁后只合并执行一次。
- 流式中间预览从上一次渲染完成后计时，原生工作越慢，恢复间隔越长，避免慢渲染吃掉自己的等待时间。WebKit 触屏间隔至少 100ms，其他触屏 80ms，桌面约 33ms，滑动期间至少 250ms；重渲染额外恢复间隔可到 1 秒。文字会分批出现，最终消息、工具调用收尾和停止后的最终文本立即渲染；原生较低帧率继续生效。触屏生成期间临时降低气泡毛玻璃开销，结束/停用恢复。未知接口与代写用户输入保持原生处理。
- 移动端区分横向 Swipe 与纵向滚动，减少误切消息。
- 编辑已有正则或切换开关时，只刷新原始消息中可能受该条正则影响的内容；无关的剧情选项、状态栏和人物面板保持原样。
- 只修改正则名称或只影响提示词时不刷新聊天；调整顺序、作用范围或使用过于宽泛的查找式时才安全刷新全部已显示消息。
- 正则面板新增“整理正则”：可搜索、按全局/预设/角色范围筛选，并把带 `[合集名]` / `【合集名】` / `「合集名」` 等前缀的规则自动收纳到同一合集。“合集自动折叠”默认开启，标题直接显示在原正则列表中，展开后该合集的完整正则行集中显示在标题下方；未分类规则默认展开。关闭整理栏后仍可折叠合集。
- 合集标题旁保留“选择此合集”，收起时也能一键勾选；需要拖拽时点击“调整顺序”，调整后点击“返回合集”。合集只改变显示排列，实际正则执行顺序保持原值。
- 全局、预设和角色的折叠状态各自独立；即使都叫“未分类”或使用同一合集名，点击一处也不会展开或收起其他范围的合集。
- 分组标题旁的“改名”支持重命名现有分组，包括把当前未分类规则收进一个自定义组。整理栏的“管理分组”支持选择范围新建空组、把已勾选规则移入指定组或移回未分类；未手动归组的规则继续按名称前缀自动分类。同一范围内重复名称会提示；自定义分类随酒馆设置保存，不改写正则名称或定义。不同预设按 API 与预设名隔离，不同角色按头像文件标识隔离；关闭优化后恢复原列表，分类设置仍保留。
- 整理框根据实际容器宽度布局，窄侧栏和手机自动换行，不依赖整个窗口的宽度；输入框、下拉框、复选项、分组标题与改名表单都限制在面板内部，继承当前主题的颜色、字体和控件美化。
- 开启批量编辑或整理栏后，可直接点正则名称勾选，支持 Shift 连选和可选的按住划选；批量启用、停用、移动、导出与删除仍使用 SillyTavern 原生按钮。
- 行内 ↪ 用于拖拽归组：拖向分组标题或浮出的分组目标后松手；拖动已选行时，同范围内其他已选规则一起归组。“调整顺序”模式也提供 ↪，原有 ☰ 继续调整实际执行顺序，两者互不替代。拖出目标、取消手势或切换角色/预设时不会提交归组；靠近滚动区域上下边缘可自动滚动。
- 开启“按住名称划选多条”后，按住名称连续滑动可选择/取消选择，快速跨过的中间行会补齐，原生批量工具栏每帧只通知一次，减少多条选择的重复扫描。未开启时仍可正常滑动页面。
- 单条和批量删除保留官方弹窗确认，同一范围只调用一次原生保存，成功后才移除对应行；失败保留未完成项，跨范围部分完成会提示。不会完整重读聊天，成功操作合并交给精准刷新。编辑保存显示处理中并拦截重复提交，未修改时直接关闭；等待期间继续输入的新草稿会保留在窗口中。服务器本身的预设/角色保存等待仍存在。
- 单条局部刷新失败不会拆掉整段聊天；SillyTavern 局部刷新接口整体不可用时保留聊天并提示，不额外重读聊天。

### 界面操作优化

- 预设、正则和世界书的实际执行顺序仍用 SillyTavern 原生拖拽和保存；正则 ↪ 只修改本插件的分组设置。
- 预设在电脑与手机上都只允许从左侧 ☰ 手柄开始排序，至少按住 150ms 并移动 10px；名称、开关和编辑区可正常点击或滑动翻页。更严格的现有拖拽阈值会保留，关闭“界面操作优化”后恢复原来的设置。
- 插件不禁用官方 sortable，也不在拖动期间二次渲染预设列表；只有用户显式开启“按住名称划选多条”时，才在正则名称区处理该次划选手势，拖拽手柄仍由官方处理。
- 生成期间可以连续切换预设条目，图标和当前行会立即变化并保存；生成解锁后才合并执行一次 Token 重算。
- 手机和触控笔只有在同一预设开关上按下、未滑动超过 10px 且未被系统取消时，才于抬起时即时切换，并过滤随后的重复点击；鼠标仍在 click 时切换。滑动离开后再滑回、滑到其他开关以及翻页取消均不会误切换。
- 全平台看护 SillyTavern 原生 modal 关闭流程：只有已经失效的透明关闭/加载遮罩才会被自动解除，真正活动的弹窗和加载任务保持阻塞。
- 用户明确点按聊天输入框却没有获得焦点时，插件才会核对 `disabled`、`readonly`、`inert`、可见性与命中元素；确认可输入后恢复焦点，不定时抢焦点，也不影响其他编辑框。
- 残留层挡住普通按钮时只解除已经确认失效的 blocker，不替用户重放点击；高级信息和控制台会记录恢复原因、阻塞元素、次数与浏览器环境。
- 快捷回复执行窗处于透明最小化状态时，点到背景会将控制窗展开，但不会擅自终止正在执行的脚本。
- 桌面顶栏抽屉保持 160/130ms 的官方高度展开；1000px 以下粗指针设备的普通顶栏抽屉改为一次完成高度布局，只做 `transform + opacity` 合成动画，普通触屏为 90/70ms，iPhone/iPad 为 80/60ms。
- 手机普通顶栏抽屉打开期间持续关闭实时毛玻璃，避免动画结束重新创建 blur 图层；左右大抽屉、桌面布局与系统“减少动态效果”保持官方行为。
- Popup 直接跟随 SillyTavern 官方 `[opening]` / `[closing]` 生命周期采用同档时长，关闭阶段立即停止重复交互，动画结束由官方流程清理。
- 拖动预设、世界书或正则时，只对包含官方 sortable helper 的当前面板临时移除模糊、阴影和过渡；排序、落点与保存仍全部交给 SillyTavern。
- 弹窗自愈不再监听整个页面的所有 `class` 变化；全局只筛选弹窗结构变化，具体状态只监听具体弹窗，并把同一帧的检查合并一次。
- 生成期间切换不会改变已经发送给模型的当前请求，从下一次生成、继续或重新生成开始生效。

```bash
git clone https://github.com/soso454u/SillyTavern-Cloud-Lounge-Accelerator.git plugins/cloud-lounge-accelerator
```

```text
Initializing plugin from .../cloud-lounge-accelerator/server/index.js
```

## 更新与修复

2.1.28 新增低开销的交互与启动诊断：仅在复制、剪切、粘贴、选区变化和实际指针事件发生时记录事件阶段、安全元素标识、命中层、控件/祖先状态及相关异常，不读取消息正文或剪贴板内容。异常会区分遮罩命中、传播中断、控件禁用/不可命中、指针捕获残留、业务异常、主线程繁忙或无法确认，并把最近一次异常限量保存在本机；重启 Web App 后可在“高级信息”点“复制诊断”。启动诊断记录 `SETTINGS_LOADED`、`APP_INITIALIZED`、`APP_READY`、启动遮罩消失、慢请求、请求次数/响应大小、Navigation/Resource Timing 与 Long Task 支持状态，不提前关闭官方遮罩；已完整到达 click 的按钮不会因祖先短暂的 `pointer-events` 状态被误报。源码核对确认当前版未再全局释放 pointer capture；在获得真机证据前不改写 SillyTavern 的复制流程。

2.1.27 减少手机启动加载期间的插件开销：角色库、头像及背景库请求不再复用并克隆响应；云端配置与缓存统计在酒馆 `APP_READY` 后才读取，多个状态更新共用刷新，配置结果短时复用。启动完成时复用已经挂载的设置面板，避免重建和重复请求；保存配置后旧读取响应不能覆盖新状态。此版本减少插件自身负担，实际进入时间仍取决于网络、酒馆版本、角色库和其他扩展的初始化；iOS 官方启动遮罩仍保持到就绪。

2.1.26 修复同名合集跨范围联动：全局、预设和角色分别记录展开状态，点击全局“未分类”不会再带动预设或角色的“未分类”；其他同名合集也独立折叠。一键选择合集继续只选择该列表的匹配规则。

2.1.25 将合集折叠移到原正则列表中：同合集的完整正则行集中显示在标题下方，收起后只显示标题和“选择此合集”，不再在顶部整理栏放一组独立折叠卡片。关闭整理栏后仍然保留列表内折叠，并修复酒馆行样式覆盖隐藏状态的问题；新增 `「合集名」` / `『合集名』` 识别。拖拽排序通过“调整顺序 / 返回合集”切换，实际执行顺序与保存数据保持原样。

2.1.24 为正则整理栏新增默认开启的“合集自动折叠”选项：带合集前缀的规则初始收起，点标题在下方展开完整原生规则行，可直接选择整个合集；未分类规则默认展开。关闭该选项即恢复 2.1.23 的普通合集下拉筛选，选项会在当前浏览器保存。

2.1.23 新增“聊天显示”分页，可自定义每页 1–50 条消息，修改后当前聊天会按新数量重载；正则面板新增合集收纳、搜索、范围筛选、点名称勾选、Shift 连选和可选划选。iOS/iPadOS 不再于 `SETTINGS_LOADED` 提前撤掉启动遮罩，而是等待 SillyTavern `APP_READY` 后再开启交互看护，避免手机慢启动时露出尚未绑定的按钮。

2.1.22 修复手机打开或切换大聊天后突然无法滚动、严重时 WebContent 进程被系统终止并自动重载的高风险路径：插件不再 `clone()` `/api/chats/get` 与群聊读取响应并第二次执行完整 JSON 解析。聊天复杂度仍在官方 `CHAT_CHANGED` 后从 SillyTavern 已有内存数据计算，5 条显示、模型上下文、聊天文件和保存流程均不改变。

2.1.21 修复反向代理已有强缓存时 Service Worker 反而为静态资源增加约百毫秒等待的问题：插件会检查 `/style.css` 与 `/script.js` 的实际响应缓存头，两者剩余新鲜期都至少 5 分钟时自动注销 Worker，让浏览器直接使用原生 HTTP/disk cache；否则保留 Worker 作为普通 VPS 的静态缓存。Worker 模式同时复用 CacheStorage 句柄并降低预热并发。切换到原生缓存后，高级信息会显示“原生缓存”；已有页面在下次重新加载后完全脱离旧 Worker 控制。

2.1.20 新增“聊天保存上传压缩”：一键安装/更新默认安全写入 `performance.requestCompression`，256KB 以上请求使用官方 gzip、取消 8MB 上限并把压缩超时放宽到 15 秒；设置面板可独立开关。保存仍走原生完整覆盖、完整性检查和备份，不改写聊天数据。另明确说明：本插件的 5 条限制只影响 DOM 显示；聊天补全预设若关闭或缺少 `chatHistory` marker，SillyTavern 会跳过过往消息注入。

2.1.19 整理内部代码结构：设备与触控环境统一由一个工具模块识别，入口运行模块集中管理，三个设置开关各自维护启停流程；同时移除界面动画中已经停用的帧句柄代码。此版本不改变功能和设置，保留 2.1.18 的 iOS 输入框即时显现修复。

2.1.18 修复 iOS Safari 点按聊天输入框后键盘已出现、输入区却要等输入第一个字才显现的问题。插件只在 iPhone/iPad 的聊天输入框仍保持焦点时，跟随 `visualViewport` 变化并用浏览器原生 `scrollIntoView()` 让它进入可见区域；不恢复旧版的输入区平移，不修改聊天高度、聊天滚动、文字或光标。键盘收回后仍由 SillyTavern 原生布局自然归位。

2.1.17 修复开启“界面操作优化”后，从角色详情跳转关联世界书，点击世界书内容却关闭面板的问题。插件不再改写酒馆原生的抽屉层级规则，手机端世界书也能正确显示在角色详情上方。升级后请重新加载页面，让旧版写入 CSSOM 的规则恢复。

2.1.16 恢复 SillyTavern 原生输入布局：移除单独上抬输入区的键盘补偿和主动归零动画，聊天区与输入区重新保持同一 flex 布局关系。原生键盘出现时的视口移动仍由浏览器与酒馆版本决定；此版本不额外修改聊天高度、滚动或输入选区。弹窗自愈优先完成酒馆自己的关闭流程，并保留正在执行的快捷回复、活动加载任务与编辑框焦点。请同步更新 UI 与服务端目录、重启 SillyTavern，并重新加载 Safari 页面以卸载旧版监听器。

2.1.15 的预设正则总开关与扩展面板折叠修复一并保留。

遇到样式、Worker 或资源不同步时，打开面板点击“修复插件”。它会：

1. 停止本插件的前端优化模块。
2. 注销本插件的 Worker 并只清理本插件缓存。
3. 检查原生 HTTP 缓存；仅在缓存策略不足时重新注册 Worker、读取登录后的版本签名并预热当前资源。
4. 重新启动已开启的三个功能区。

它不会删除聊天、角色卡、世界书、预设或服务器配置。

## 安全与边界

- 服务端插件只提供健康检查、Service Worker 脚本和明确授权的性能配置接口；配置写入只处理安装器控制项、`enableKeepAlive`、`performance.lazyLoadCharacters` 或 `performance.requestCompression`，不读写聊天、角色卡或密钥。
- 页面缓存只改善第二次及以后访问的静态资源往返，不会缩短 AI 生成时间。
- 第一次访问速度主要依赖服务器、线路、TLS、反向代理和 SillyTavern 本身。
- 如果根作用域已有其他 Service Worker，本插件拒绝覆盖。
- SillyTavern 不应在没有账号、访问控制或可信网络边界时直接暴露到公网。

## 开发与发布检查

可读源码仍在 `index.js`、`modules/`、`ui/` 等目录，`manifest.json` 使用已提交的 `dist/index.js`。维护时修改源码，再生成发布文件；不要直接编辑 `dist/`。

```bash
npm ci
npm run build
npm run check:build
npm test
```

`check:build` 核对发布文件是否与当前源码、版本和锁定的打包工具一致，并拒绝遗留的旧代码块。用户安装或更新插件不需要运行这些命令，服务端入口仍为 `server/index.js`。

可选的 `scripts/check-client-bundle.mjs` 使用 Playwright 及本机 Chromium，加载实际发布文件，验证桌面/手机环境的启动依赖数量、原生模块路径、就绪后加载、聊天显示条数、正则整理和停用清理；测试使用模拟酒馆接口。
